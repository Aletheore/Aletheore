This is a deliberately injected bug for the benchmark, not a real historical fix. A new package-level request counter is incremented with a plain `requestCount++` inside `ServeHTTP`, which Gin (via net/http) calls concurrently from many goroutines - one per in-flight request. Because the increment isn't atomic or mutex-protected, concurrent requests can race on it, silently losing counts (and `go test -race` would flag it as a data race).
