JUnit 4's `AssumptionViolatedException` - thrown when a test's assumptions aren't met - could not be serialized in the common case where the matcher or value it captured wasn't itself serializable, throwing a `NotSerializableException` instead. This broke test runners that serialize exceptions across a process boundary, such as forked test JVMs. The fix adds a custom serialization path that safely captures a description of the matcher/value instead of the raw objects.
