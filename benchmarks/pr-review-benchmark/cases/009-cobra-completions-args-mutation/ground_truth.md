Cobra's shell-completion logic could silently corrupt a program's own `os.Args` slice, because of a subtle Go slice-aliasing bug: appending a completion sentinel to a re-sliced view of the arguments sometimes wrote into the shared backing array instead of a fresh one. Any code path that inspected `os.Args` after completions ran (for example, a custom `ValidArgsFunction`) could see corrupted data. The fix copies the slice before appending to it.
