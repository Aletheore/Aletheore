# Methodology

- **Run date:** 2026-09-19 (5-way run, Aletheore direct-invocation bare-prompt methodology)
- **Deployed baseline:** production commit `84c8cdd`, tag `github-app-deploy-2026-09-19` — includes PR #746 (sibling-file-in-same-directory evidence) and PR #747 (softened confidence bar for lower-severity findings), both merged and deployed same night as this run.
- **Aletheore (Flash tier only — not AIR):** `glm-5.3-flash` via IndieRouter (production's real current default generation adapter, `flash_review_generation_adapter()` in `model_tiers.py`), `verify_with_second_model=False` (explicitly Flash tier, no AIR-tier DeepSeek verification pass). Scored via direct `review_diff()` invocation against the post-#746/#747 deployed code, **with `referenced_symbol_context=""` and `sibling_file_context=""`** — matching the Martian benchmark's own real methodology (external repos Aletheore never scanned there either). This is a deliberate methodology choice, not the same as production's real default behavior, which feeds both context blocks on every real PR review — see REPORT.md's Headline section for the full real numbers behind this choice: bare prompt measured 90.0% recall / 100.0% precision on this corpus vs. 65.0% / 93.8% with production's actual default context enrichment, controlled, same model, same cases, everything else held constant.
- **PR-Agent:** `gpt-5.6-luna` (`--config.model=gpt-5.6-luna`), its existing real config from prior runs — kept unchanged rather than force-matched to Aletheore's current model, since Aletheore's shipped default (GLM-5.3-Flash) is a deliberate, separately-validated cost decision (PR #730) and forcing it onto PR-Agent via an untested LiteLLM/IndieRouter integration was judged higher-risk than documenting each tool's real current config honestly. All 24 cases run fresh this session.
- **DeepSource, Sourcery, Greptile:** real hosted GitHub App reactions on the scratch repo (`ArihantK15/proctor-browser`), fetched via each tool's own real PR comment/review-comment surface. All 24 case PRs were closed and reopened fresh partway through this run after discovering Sourcery/Greptile's Apps react reliably to a genuine "PR opened" event but not to a force-push "synchronize" event on an already-existing PR — this fixed an initial false appearance that Greptile was entirely absent/uninstalled.
- **LLM judge:** Claude, 4 fresh subagent dispatches (one per 6-case batch, `general-purpose` agent type), each with zero knowledge of this session — genuinely blind. Findings passed were the 5 real tool names (named comparison, not anonymized — see README.md). Recall agreement between manual (Step 4) and LLM-judge (Step 5) scoring: 98.3%. Actionability agreement: 57.3% (expected noise on a subjective 1-5 scale).
- **Corpus:** 24 of 25 cases — 15 real bug-fix reconstructions, 5 injected bugs, 4 clean diffs, across Python/JavaScript/Go/Java. Case `020` excluded (corpus fixture/push-protection placeholder issue, consistent with prior runs).
- **Isolation split test (resolved; see REPORT.md's Headline table for full numbers):** `referenced_symbol_context`-only and `sibling_file_context`-only were each run twice, independently, to find out which of the two context blocks the bare-prompt condition drops is actually responsible for the recall/precision cost. `referenced_symbol_context`-only tracked bare prompt closely both times (90.0%/95.0% recall) — not the problem. `sibling_file_context`-only replicated almost exactly both times (75.0% recall, 1/4 clean false positives, 94.7% precision in both runs) — the tightest, most reliable isolated result of anything measured in this run, and it alone reproduces most of the full enriched-context regression (65.0%). **Production change made on this basis:** PR #748 stops `jobs.py` from feeding `sibling_file_context` into the live Flash Review prompt; `referenced_symbol_context` is untouched.
- **This conflicts with PR #746's own original validation**, which measured a +6.6pp recall gain from `sibling_file_context` on the separate ~50-PR Martian corpus. Not reconciled here — stated plainly as an open question about how the feature's effect varies by corpus/diff shape. This 24-case run (cross-tool, LLM-judge-corroborated, replicated per variant) is treated as more decisive for the production call than the single-measurement Martian result, not because the Martian number is assumed wrong.
- **A separate real defect found, independent of the context question:** on at least 2 of the enriched-context run's misses (cases 003, 006), GLM-5.3-Flash correctly diagnosed the real bug but `review_diff()`'s own content-grounding validation gate silently dropped the finding (logged: "quoted content wasn't near the cited line"). Filed as a real product bug, not a benchmark artifact.
- **Prior runs, superseded:** the 2026-08-30 run (tag `github-app-deploy-2026-08-30`) compared Aletheore AIR/Flash on `gpt-5.6-luna` against PR-Agent-on-Luna (true model parity, no Greptile/limited DeepSource). This run trades that model parity for testing Aletheore's real current shipped model (GLM-5.3-Flash) and adds real Greptile + DeepSource data; PR-Agent stays on Luna, so this run is "each tool's real current config" rather than architecture-only model-held-constant comparison. An Aletheore-on-Luna variant was also run this session for reference (see `results/raw_flash_luna/` — not included in the headline table, since the real story this run surfaced was the context-enrichment effect, not model choice).
