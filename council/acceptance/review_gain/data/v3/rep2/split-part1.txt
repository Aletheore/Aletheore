1. `pyrsistent/pyrsistent/_pdeque.py`, `PDeque._append`, line 213. The new length is `self._length - 1`. Appending an element should give `self._length + 1`. Every unbounded `append` or `appendleft` shrinks the recorded length.
2. `pyrsistent/pyrsistent/_pbag.py`, `PBag.__eq__`, line 148. It returns `self._counts != other._counts`. It should return `==`. As written, equal bags compare unequal and unequal bags compare equal.
3. `pyrsistent/pyrsistent/_pset.py`, `PSet._Evolver.persistent`, line 132. The condition is flipped. A dirty evolver returns the original pset and discards the changes. A clean one builds a new `PSet`. It should be `if not self.is_dirty(): return self._original_pset`.
4. `funcy/funcy/calc.py`, `CacheMemory.expire`, line 98. The condition is `entry is not None or entry[1] <= expires_at`. It should use `and`. With `or`, a missing entry (`None`) makes `entry[1]` raise `TypeError`. A live entry that was refreshed later also gets evicted.
5. `funcy/funcy/strings.py`, `_make_getter`, line 15. The condition is `regex.groups == 0 and regex.groupindex == {}`. It can never be reached, because the first branch already handles `groups == 0`. It should be `regex.groups == 1 and regex.groupindex == {}`. Single-group regexes currently return a tuple from `groups()` instead of the group string.
6. `schema/schema/__init__.py`, `_get_type_name`, line 616. The check is `python_type != str`. It should be `== str`. As written, every type other than `str` maps to `"string"`, so `int`, `float`, `bool`, `list` and `dict` never reach their own branches.
7. `schema/schema/__init__.py`, `_invoke_with_optional_kwargs`, line 345. The check is `len(s.parameters) != 0` and it returns `f()`. It should be `== 0`. A callable that accepts kwargs currently gets called without them, and a zero-argument callable gets called with kwargs.
8. `pyrsistent/pyrsistent/_pdeque.py`, `PDeque._tip_from_lists`, line 89. It uses `secondary_list[-0]`, which is index 0. It should be `[-1]`. If the primary list is empty, `left` and `right` return the wrong end of the other list. This happens whenever the deque has more than one element and the primary list is empty.
