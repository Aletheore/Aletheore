Behavior Regression: The first regex was narrowed from \b(?:top|which|show|list)\s+(\d{1,2})\b to only \btop\s+.... Questions that previously produced a limit now fall through to the default of 10, e.g. "list 5 largest files", "show 3 most complex modules" (the second pattern only matches "N most", not "show 3 most..."), or "which 5 files are largest" (the new third pattern only matches the specific "imported/depended on by the most" phrasing). Unless the intent was deliberately to restrict ranking cues, this silently changes routing for existing query forms.

🟡 Medium · #1 of 2

Overly broad patterns: The new cycles intent matches the bare words \bcycles?\b / \bcircular\b and the hubs intent matches \bhubs?\b, each with weight 1.5. These words appear frequently in non-import questions ("how does the render cycle work", "what is the retry hub", "circular buffer implementation"), and because both intents are also added to the rival-exemption list in route(), a match on them bypasses the low-confidence tie-break that normally protects against a confident wrong answer. A question like "explain the event cycle in the scheduler" would route to find_import_cycles at high confidence instead of a code-search intent. Consider requiring an import/dependency context word near the cycle/hub term, or not exempting these intents from the rival check.

Recall regression: The cycles intent previously matched the bare words cycles? and cyclic, so questions like "are there any cycles in the dependency graph?" or "find cyclic modules" routed to import_cycles. The new patterns only match when the word circular/import/dependency is adjacent (e.g., "circular imports", "import cycles"), so plain "cycles" or "cyclic" questions no longer trigger this intent at all. If the goal was to reduce false positives, a narrower but still inclusive pattern (e.g., keeping \bcycles?\b with lower weight, or adding \b(?:dependency|module) cycles?\b) would preserve recall. Same concern applies to the hubs pattern: "which files are hubs?" no longer matches now that \bhubs?\b requires an import|dependency prefix.
