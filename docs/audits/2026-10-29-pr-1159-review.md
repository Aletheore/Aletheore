# PR 1159 review

Scope: the complete website companion/chat PR, its backend gate, Redis scripts, public-source corpus, tests, configuration and deployment documentation. Dependency PR 1158 is reviewed separately; this PR does not add a terminal pet or greeting.

## Findings and fixes

- Decouple network quota identity from service-token rotation. A separate stable HMAC secret is now required; missing configuration denies admission. Global budget accounting remains unchanged.
- Bound backend Redis operations independently of the queue client: a dedicated four-connection async pool, explicit 0.5-second connect/socket timeouts, zero retries and a 1.5-second operation deadline. An outage cannot occupy the shared thread executor. The original shared client already had 0.5-second socket timeouts; the automated claim of an indefinitely blocked socket was conditional rather than established.
- Handle backend disconnects cleanly. Return consistent upload-abort statuses, reject malformed media types/UTF-8 and recheck cancellation after admission before inference. A provider usage-contract violation in the classifier now stops the second model call immediately.
- Close the companion when following source/privacy/documentation links while retaining in-memory history. Previously mobile visitors could navigate behind an open modal. Bound browser waiting to 35 seconds with a normal AbortController timer, avoiding a dependency on newer browser AbortSignal combinators.
- Make paid-evaluation output portable with the platform temp directory. Check writability before spending, persist every completed case and early-stop reason, and stop after unknown usage rather than continue spending without reliable accounting. Ordinary unit tests cover these paths without a model key.
- Narrow labelled demo fixture matches to whole words and explicit overview requests. Strengthen tests against reflected input, markup, command and source-link injection. Decode common/numeric public-document entities as literal text, keep retrieval IDs unique and avoid joining the free price directly to “forever.”
- Make operator status explicitly fail for missing/corrupt ledger state. It never initializes or resets accounting.
- Close the CI gap: website tests, type generation/checking and lint on Windows/Linux/macOS with Node 22/24; browser regressions on each OS's Node 22 job; real Lua tests on Redis 7 in Linux. Align package engines with pinned Vitest 5 (Node 20 is unsupported). Redis itself remains a Linux container service; the browser/client and development tooling are portable.
- Preserve synthetic grounding, injection and HTTP/outage/restart evidence in the repository. Date-scope earlier test counts and replace stale process-local-limit wording with current shared-limiter status.

## Remaining deployment requirements

Public inference remains disabled. Migrate existing Redis data before applying the new named volume; verify the actual Docker/Vercel transport, stable secret distribution, persisted ledger and proxy-header provenance. Configure a dedicated provider hard spend cap and update privacy disclosures before a separately approved public activation. Do not replace the static-layout development flag with an accidental production switch.

The exact production Vercel forwarded-header path still requires deployed verification. The trust assumption follows [Vercel's request-header documentation](https://vercel.com/docs/headers/request-headers), not arbitrary caller headers. Network limits are not authenticated user quotas; distributed callers can exhaust the permitted global allowance. Provider billing changes, other credential users, stale-data restoration and raw hosting traffic need the external controls documented in the spend-limit spec.

Real iOS/Android keyboard behavior, Safari/Firefox and assistive-technology testing remain unverified. Chrome mobile viewport tests establish layout/modal behavior, not real-device coverage or universal injection resistance. The corpus is deliberately smaller than the full CLI manual and must continue abstaining on unsupported details.
